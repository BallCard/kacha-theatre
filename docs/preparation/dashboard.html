赛道二：内容重构 — 让视频成为生活搭子

▼

核心目标：将视频内容转化为用户能看懂、能学到、能用上的体验

维度权重关注点
用户价值感30%内容是否转化为可理解、可判断或可执行的能力；是否提升学习/决策/行动效率
AI能力与产品结合20%AI是否参与内容理解/重构；是否改变内容使用方式
创新性与延展潜力20%是否提出新的内容消费或使用方式；是否具备扩展空间
场景与问题洞察15%是否选取了有价值的内容场景；是否清楚目标用户；内容是否值得被转化
体验完整性15%是否可被直接体验；是否形成基本闭环

适合方向

📹 教程视频

→ 可执行的步骤清单 / 交互式指南

🍳 美食视频

→ 个性化菜谱 / 购物清单 / 营养分析

📖 知识视频

→ 结构化笔记 / 知识图谱 / 学习路径

📊 评测视频

→ 对比表格 / 决策助手 / 个性化推荐

参考作品：随厨小食堂（2025获奖）—— 美食视频 → 可执行的烹饪指南

值得学习：高频场景、明确可执行的价值、完整闭环（视频→指南→实操）

赛道四：视觉搜索 — 视觉 + 语音，所见即所想

▼

核心目标：围绕真实场景，把从用户触发到体验展开的过程讲清楚

维度权重关注点
AI能力与产品结合30%是否在关键环节合理使用视觉理解等AI能力；是否讲清楚技术如何支撑体验展开
体验完整性20%是否围绕完整用户旅程（从触发到持续探索）；各环节衔接是否自然
用户价值感20%是否让用户在过程中获得实际帮助、启发或兴趣延展；是否超越简单"知道是什么"
场景与问题洞察15%是否构建了真实且自然的视觉触发场景；是否贴近日常使用路径
创新性与延展潜力15%是否提出新的视觉交互方式或体验路径；是否具备扩展为完整产品的可能性

适合方向

📸 拍照识物

🏞️ 场景识别

黑客松实战经验

▼

执行力和找到谈得来的伙伴最重要，点子是其次。

✅ 应该做的

  • 快速验证核心价值
  • 用户体验优先
  • AI 能力突出
  • 完整闭环
  • 真实场景

❌ 不该做的

  • 过度工程化
  • 功能堆砌
  • 技术炫技
  • 忽视演示准备
  • 单打独斗

⚡ 功能取舍

  • 设计阶段：砍 70%
  • 开发中期：再砍 50%
  • 演示前：只展核心
阶段时间关键任务
需求与设计3h确定赛道、场景、核心功能、技术方案，砍掉 70%
核心功能开发12hAI 能力集成、核心交互流程，先做最重要的
体验优化5hUI/UX、流程打磨，保证演示流程顺畅
演示准备3h海报、简介、演示脚本，边开发边准备
缓冲2h应对突发问题，一定会用到

🎯 最重要的事（按优先级）

  • 1. 产品特色要明显 — 让人一眼看出你在做什么
  • 2. 核心功能必须完成 — 其他可以 mock，核心必须能跑
  • 3. 能上台 demo — 完整流程 > 完美细节

快速决策参考

▼

🔧 技术选型

  • 优先选择团队熟悉的技术栈
  • API 要提前测试可用性和速度
  • 准备备用方案（Plan B）

⏰ 时间分配

  • 前3h：需求与设计（含砍功能）
  • 中间12h：核心功能开发
  • 后5h：体验优化
  • 最后3h：演示准备
  • 预留2h：缓冲

👥 团队协作

  • 明确决策机制（谁拍板）
  • 快速达成共识，先做再说
  • 遇到问题及时沟通，不闷头做
  • 非技术成员负责砍功能和演示

🎤 演示要点

  • 提前准备演示视频作备份
  • 准备效果好、有冲击力的测试数据
  • 添加 loading 动画，避免卡顿感
  • 友好的错误提示

Token 成本优化策略

📉 核心优化

  • 智能采样：按场景变化采样，不每帧分析
  • 压缩图片：降低分辨率，减少 token
  • 批量处理：一次请求分析多帧
  • 缓存结果：相似帧使用缓存

🛡️ 风险控制

  • API 限流：准备多个 Key 轮换
  • 模型效果：准备多个模型备选
  • 网络问题：准备热点备用
  • 代码丢失：频繁 push 到 GitHub
