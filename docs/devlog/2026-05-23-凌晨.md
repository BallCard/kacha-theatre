## 触发事件

队友凌晨提交了一份新需求文档（已归档至 [docs/requirements/咔嚓剧场需求文档-队友版-2026-05-23.docx](../requirements/咔嚓剧场需求文档-队友版-2026-05-23.docx)），提出：

2. 部分 2：基于运势卡展开 5 节点互动剧情，6 种结局，最后导出连环画
3. 题材建议放弃"摸鱼"约束，扩展到通用运势场景

## 讨论与权衡

### 关键问题：保留 vs 放弃"摸鱼"主题

| 方向 | 优点 | 缺点 |
|---|---|---|
| **保留摸鱼** | 视觉锚点强、已有工程全复用、调性稳 | 题材限办公室、剧情发挥窄 |
| **放弃摸鱼** | 题材丰富、剧情发挥大 | 视觉锚点退化、后端前端大改、调性割裂 |
| **折衷（最终选定）** | Part 1 摸鱼不动 + Part 2 在办公室语境下做 5 节点剧情 | 题材聚焦但能撑（办公室短剧本是抖音富矿） |

### 决定

**保留摸鱼 + 加 Part 2 剧情游戏作为纯增量**。理由：

1. 赛道四"真实视觉触发场景 + AI 能力差异化"两条评审锚点全保住
2. 后端 T1-T13（已完成 13 次提交）+ 前端 MVP 接入零改动
3. 御史腔 system prompt 不动，避免"御史皮 + 网络热梗"的调性割裂
4. 办公室摸鱼短剧本身在抖音内容生态里是富矿，5 节点足够撑反转

详细对比和判定见 [ADR-004](../decisions/004-Part2-剧情游戏增量.md)。
