# 比赛记录系统使用指南

## 系统概览

这是一个为黑客松队长设计的完备记录系统，涵盖：
- ✅ 团队协作留痕
- ✅ 开发过程记录
- ✅ 决策追溯
- ✅ 复盘总结

## 使用流程

### 阶段1：比赛开始前（现在）
1. ✅ 填写 `docs/team.md` 的团队成员信息
2. ✅ 确认协作渠道（微信群、飞书等）

### 阶段2：5.23 上午（赛题发布）
1. 📝 在 `docs/devlog/2026-05-23-上午.md` 记录赛题解读
2. 📝 填写 `docs/decisions/001-赛道选择.md` 的决策过程
3. 📝 填写 `docs/decisions/002-技术栈选择.md`
4. 📝 如果开会讨论，在 `docs/meetings/` 创建会议纪要

### 阶段3：开发过程（5.23-5.24）
1. 📝 每4-6小时更新一次开发日志：
   - `docs/devlog/2026-05-23-下午.md`
   - `docs/devlog/2026-05-23-晚上.md`
   - `docs/devlog/2026-05-24-上午.md`
2. 📝 重大决策记录到 `docs/decisions/`
3. 📝 关键会议记录到 `docs/meetings/`
4. 💾 设计稿放到 `design/` 对应目录
5. 💾 游园会海报放到 `design/poster/`

### 阶段4：比赛结束后
1. 📝 填写 `docs/retrospective.md` 完整复盘
2. 📝 更新 `README.md` 的项目成果
3. 📸 添加照片、视频链接

## 核心文档说明

### 1. 开发日志（devlog）
**用途**：记录开发过程的关键进展、问题、解决方案

**更新频率**：每4-6小时

**重点记录**：
- 技术难点和解决方案
- 创新点
- 踩过的坑
- 时间分配

### 2. 决策记录（ADR）
**用途**：记录重要决策的背景、选项、理由、后果

**何时记录**：
- 赛道选择
- 技术栈选择
- 核心功能取舍
- 重大方向调整

**价值**：
- 避免重复讨论
- 复盘时追溯决策逻辑
- 为未来类似决策提供参考

### 3. 会议纪要（meetings）
**用途**：记录团队会议的讨论、决策、行动项

**何时记录**：
- 关键决策会议
- 每日站会（可选）
- 复盘会议

### 4. 复盘总结（retrospective）
**用途**：比赛结束后的完整复盘

**填写时机**：比赛结束后1-2天内（趁记忆清晰）

**价值**：
- 提炼可复用经验
- 识别改进空间
- 为下次比赛做准备

## 使用技巧

### 1. 及时记录
- ✅ 趁热打铁，不要事后补
- ✅ 用手机拍照记录白板讨论
- ✅ 关键对话截图保存

### 2. 简洁为主
- ✅ 抓关键信息，不写流水账
- ✅ 用表格、列表提高可读性
- ✅ 一句话能说清楚就不要写一段

### 3. 结构化思考
- ✅ 问题 → 原因 → 解决方案 → 经验
- ✅ 背景 → 选项 → 决策 → 理由 → 后果
- ✅ 目标 → 行动 → 结果 → 反思

### 4. 团队协作
- ✅ 指定专人负责记录（可轮换）
- ✅ 关键决策让全员确认
- ✅ 定期同步文档更新

## 常见问题

**Q: 开发太忙，没时间记录怎么办？**
A: 
- 最小化记录：只记录关键决策和重大问题
- 语音转文字：用飞书妙记等工具快速记录
- 事后补充：至少在每个阶段结束时花10分钟回顾

**Q: 哪些内容必须记录？**
A: 
- ✅ 赛道选择和理由
- ✅ 核心创意和技术方案
- ✅ 重大技术难点和解决方案
- ✅ 时间分配和进度
- ✅ 比赛结果和复盘

**Q: 记录给谁看？**
A: 
1. 给未来的自己（下次比赛参考）
2. 给团队成员（协作留痕）
3. 给简历/作品集（展示思考过程）
