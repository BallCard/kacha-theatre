# 协作模式指南

## 25小时极限开发协作策略

### 核心原则
- **并行优先**：最大化并行工作，减少依赖等待
- **快速集成**：每2-3小时集成一次，避免最后合并地狱
- **约定优于配置**：提前定好接口、数据格式，各自开发
- **Mock先行**：前后端用Mock数据并行开发

## Git协作流程

### 分支策略（简化版）

```
main (保护分支，随时可演示)
  ├── dev (开发主分支)
  │   ├── feature/frontend-ui
  │   ├── feature/backend-api
  │   ├── feature/ai-integration
  │   └── feature/design-assets
```

### 工作流程

**阶段1：初始化（11:00-12:00）**
```bash
# 队长创建 dev 分支
git checkout -b dev
git push -u origin dev

# 成员各自创建功能分支
git checkout -b feature/frontend-ui
git checkout -b feature/backend-api
git checkout -b feature/ai-integration
```

**阶段2：并行开发（12:00-22:00）**
- 每个成员在自己的 feature 分支工作
- 每2-3小时合并到 dev 一次
- 合并前先拉取最新 dev：`git pull origin dev`
- 冲突立即解决，不过夜

**阶段3：集成稳定（22:00-次日12:00）**
- 22:00 前完成核心功能合并到 dev
- 22:00 后只做 bugfix 和优化
- 次日 10:00 从 dev 合并到 main，准备提交

### 提交规范（简化版）

```
[模块] 简短描述

示例：
[前端] 完成首页布局
[后端] 实现视频解析API
[AI] 接入GPT-4V图像识别
[修复] 修复上传文件大小限制
```

## 并行开发模式

### 模式A：前后端分离（推荐）

**适用场景**：团队有明确的前后端分工

```
前端开发者 ────┐
               ├──→ 约定API接口 ←──┐
后端开发者 ────┘                   │
                                   ├──→ 定期集成
AI集成者 ──────→ 提供AI能力封装 ──┘
设计师 ────────→ 提供设计资源 ────┘
```

**关键约定**：
1. **API契约先行**：第一时间定好 `docs/api-contract.md`
2. **Mock数据**：前端用 Mock Server，后端用测试数据
3. **类型共享**：共享 TypeScript 类型定义或 JSON Schema

**时间分配**：
- 11:00-12:00：定接口、搭架子
- 12:00-18:00：并行开发核心功能
- 18:00-20:00：第一次集成联调
- 20:00-22:00：完善功能
- 22:00-次日08:00：休息+夜猫子继续优化
- 08:00-12:00：最后集成、测试、打磨

### 模式B：全栈协作（备选）

**适用场景**：团队都是全栈，或人数少（2-3人）

```
成员1：页面A + 对应API
成员2：页面B + 对应API
成员3：AI集成 + 公共组件
```

**关键约定**：
1. **按功能垂直切分**：每人负责完整的用户流程
2. **共享组件库**：提前约定公共组件接口
3. **数据库Schema先行**：第一时间定好数据结构

### 模式C：结对编程（高风险场景）

**适用场景**：遇到技术难点，需要集中攻坚

```
Driver（写代码） + Navigator（审查思路）
每30分钟轮换角色
```

**何时使用**：
- AI集成遇到复杂问题
- 核心算法实现
- 关键bug调试

## 冲突预防机制

### 文件级隔离

**严格遵守**：
```
src/
├── frontend/          # 前端开发者专属
│   ├── pages/         # 按页面分配给不同人
│   ├── components/    # 按功能模块分配
│   └── shared/        # 共享代码，谨慎修改
├── backend/           # 后端开发者专属
│   ├── routes/        # 按路由分配
│   ├── services/      # 按服务分配
│   └── shared/        # 共享代码，谨慎修改
└── ai/                # AI集成者专属
```

**冲突高发区**（需要协调）：
- `package.json` / `requirements.txt`：依赖安装前通知
- `shared/` 目录：修改前同步
- 配置文件：统一由队长管理

### 实时同步机制

**工具选择**：
- **代码同步**：Git + 每2小时集成
- **进度同步**：微信群 + 每小时报进度
- **问题同步**：遇到阻塞立即喊人

**同步模板**（微信群）：
```
[进度] 张三 14:00
✅ 完成：首页布局
🚧 进行中：视频上传组件
⏰ 预计完成：16:00
🚨 阻塞：需要后端提供上传接口
```

## 集成检查清单

### 每次合并到 dev 前检查

- [ ] 代码能正常运行（`npm run dev` / `python main.py`）
- [ ] 没有明显的 console.error 或异常
- [ ] 新增的依赖已记录到 `package.json` / `requirements.txt`
- [ ] 关键功能手动测试通过
- [ ] 提交信息清晰

### 集成后验证

- [ ] 拉取最新代码后能正常启动
- [ ] 核心流程能跑通（端到端测试）
- [ ] 没有明显的性能问题
- [ ] UI没有明显错位

## 紧急情况处理

### 场景1：合并冲突
```bash
# 1. 保存当前工作
git stash

# 2. 拉取最新代码
git pull origin dev

# 3. 恢复工作
git stash pop

# 4. 解决冲突（找对应的人一起看）
# 5. 测试后提交
```

### 场景2：代码炸了
```bash
# 回滚到上一个可用版本
git log --oneline  # 找到最后一个好的commit
git reset --hard <commit-hash>
git push -f origin feature/xxx  # 仅在自己的分支上force push
```

### 场景3：依赖冲突
- 立即在群里同步
- 统一由一个人解决依赖问题
- 其他人暂停 `npm install` / `pip install`

## 工具推荐

### 代码协作
- **Git客户端**：VS Code内置 / GitHub Desktop
- **代码审查**：GitHub PR（如果有时间）

### 实时沟通
- **微信群**：紧急事项、进度同步
- **飞书文档**：API文档、设计稿共享
- **腾讯会议**：远程结对编程（如果需要）

- **Mock Server**：json-server / MSW
- **API测试**：Postman / Thunder Client
- **实时预览**：Vite HMR / Flask debug mode

## 时间管理建议

### 个人时间分配
- **开发时间**：70%（17.5小时）
- **集成联调**：15%（3.75小时）
- **休息睡眠**：10%（2.5小时）
- **演示准备**：5%（1.25小时）

### 团队同步节奏
- **每2小时**：代码集成
- **每4小时**：团队站会（15分钟）
- **关键节点**：
  - 18:00：第一次完整集成
  - 22:00：功能冻结，只修bug
  - 次日08:00：最后集成，准备演示

## 心态管理

### 避免的陷阱
- ❌ 过度追求完美（80分能演示 > 95分半成品）
- ❌ 闷头开发不沟通（遇到问题立即同步）
- ❌ 频繁切换任务（专注完成一个功能再切换）
- ❌ 熬夜硬刚（保证至少4小时睡眠）

### 保持高效
- ✅ 优先完成核心流程（能演示最重要）
- ✅ 用AI辅助编程（Cursor、Claude Code）
- ✅ 复用开源组件（不重复造轮子）
- ✅ 及时休息（累了就休息，效率更高）

---

**记住**：25小时不是马拉松，是接力赛。每个人跑好自己的一棒，按时交接，才能赢。
