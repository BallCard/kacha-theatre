## §1 产品定位与核心闭环

### 一句话定义
给工位上摸鱼午睡的同事拍一张，AI 生成一份玄学御史报告 + 在原图上自动盖戳贴纸，可拖拽微调，一键导出朋友圈/群聊抹茶图。

### 产品名
暂名 **摸鱼御史**（候选：御史房 / 同事图鉴）。需队友 5.23 上午拍板。

### 目标用户
互联网/办公室白领，20–35 岁，熟悉抖音梗文化。日常有"摸鱼时刻"想自我嘲讽 + 群里玩梗的需求。摸鱼是社交货币，不是负面词。

### 真实场景
下午 3 点，对面工位的同事头一歪睡着了。你想发群里玩梗，但只发一张照片不够梗，配文又懒得想。这时打开摸鱼御史，3 秒拿到一张带"宜划水 · 忌开会"印章和一段中二解读的成图。

### 核心闭环（5 步，全程 < 30s）

1. **触发**：H5 首页大按钮"现在去拍一个" → 调起手机摄像头 / 相册
2. **理解**：图片传给后端 → VLM 一次调用，结构化输出 `{姿态类型, 桌面线索, 关键点坐标, 御史报告, 贴纸建议}`
3. **重构**：前端拿到 JSON → Canvas 把贴纸按坐标自动盖到原图 + 报告卡渲染
4. **微调**：用户可拖拽/缩放/删除贴纸，可点击切换"今日宜忌"
5. **分发**：一键导出竖版长图（原图 + 报告卡拼合），保存/分享 + **可选上"今日摸鱼榜"**（脸部强制盖御史印，详见 §8）

### 评审锚点对应（赛道四）

| 维度 | 权重 | 我们怎么打 |
|---|---|---|
| 场景与问题洞察 | 15% | 办公室摸鱼是高频、真实、自然的视觉触发场景 |
| AI 能力与产品结合 | 30% | VLM 输出**坐标 + 玄学解读**驱动整个视觉重构，不只是识别 |
| 体验完整性 | 20% | 触发→理解→改造→微调→分发→社区，旅程闭合 |
| 用户价值感 | 20% | 从一张睡照变成可分享的梗素材 + 社交货币，超越"知道是什么" |
| 创新性与延展 | 15% | 视觉理解 + LLM 玩梗 + 可拖拽再创作三件套，可扩展自拍/宠物/视频 |

### MVP 范围

**P0 必做**：主闭环 5 步、10–20 个贴纸素材、报告卡组件、导出长图。

**P1 升级为核心**：今日摸鱼榜（详见 §8）—— 这是社交传播主引擎，不是可选项。

**P1 锦上添花**：宠物彩蛋（VLM 自动识别走另一套 prompt）。

**P2 不做**：AI 重绘魔改、多图连拍连续剧、登录账号、长期数据沉淀。

## §2 系统架构

```
┌─────────────────────┐         ┌──────────────────────┐         ┌─────────────────┐
│  H5 前端（移动端）   │  HTTPS  │   后端 BFF (Node)    │  HTTPS  │   VLM API       │
│  Vite + Vue/React   │ ──────▶ │   单一 /analyze 接口 │ ──────▶ │  (豆包/4o/...)  │
│  Canvas + 手势      │ ◀────── │   prompt 注入 + 校验  │ ◀────── │                 │
└─────────────────────┘  JSON   └──────────────────────┘  JSON   └─────────────────┘
        │                                │
        │ 静态资源                        │ P1: 名人堂
        ▼                                ▼
   贴纸 PNG 库                  Redis / JSON 文件
   报告卡模板                   （最近 N 张匿名图）
```

### 切分理由

- **前端扛 70% 工作量**：Canvas 渲染、拖拽手势、导图合成 —— 视觉重构本来就是前端的事，后端只是 LLM 代理
- **后端只做一件事**：包一层 prompt + 把 API key 藏起来。不做业务逻辑、P0 阶段不存图
- **VLM 单次往返**：不做多轮对话，token 可控、延迟可控（目标 P95 < 8s）
- **VLM 选型待定**：豆包 / GPT-4o / Claude / 通义千问 中选一家，决策标准为 token 价格 + 中文调性 + JSON 输出稳定性。5.23 上午定。

## §3 模块拆分

### 前端 5 个模块

| 模块 | 职责 | 难点 | 负责人 |
|---|---|---|---|
| Capture | 调摄像头/相册、压缩到 1024px、上传 | 移动端兼容 | 前端 A |
| Analyzer Client | 调 `/analyze`、loading 动画、错误兜底 | 等 8s 不能让用户走 | 前端 A |
| Stage | Canvas 渲染原图 + 贴纸图层 + 拖拽手势 | 多指缩放/旋转 | 前端 B |
| ReportCard | 报告卡组件，宜忌可点击切换 | 文案模板 | 前端 B |
| Exporter | Canvas + 报告卡合成竖版长图，下载/分享 | iOS Safari 下载坑 | 前端 A |

### 后端接口契约

```
POST /analyze
  body: { image: base64 }
  resp: {
    pose_type: "趴桌型",            // 姿态分类
    desk_objects: ["咖啡", "键盘"],  // 桌面线索（玄学素材）
    moyu_index: 87,                // 摸鱼指数 0-100（榜单 AI 分）
    report: {
      title: "划水大将军",          // 御史封号
      paragraph: "紫微星偏移3度...", // 中二解读 50-80字
      yi: ["摸鱼", "划水", "假装思考"],  // 今日宜
      ji: ["开会", "改PPT", "接电话"]    // 今日忌
    },
    face_boxes: [                  // 人脸框，归一化坐标，用于强制盖印
      { x: 0.32, y: 0.18, w: 0.24, h: 0.28 }
    ],
    stickers: [
      // 坐标归一化 0-1，前端按实际尺寸还原
      { type: "seal_red",   text: "划水大将军", x: 0.78, y: 0.12, rotate: -8 },
      { type: "bubble",     text: "ZZZ",      x: 0.45, y: 0.30, rotate: 0 },
      { type: "yellow_tag", text: "摸鱼+20",   x: 0.18, y: 0.82, rotate: 6 }
    ]
  }
```

`type` 字段对应前端贴纸素材库的 PNG 资源。`text` 由 LLM 动态生成，前端做文字渲染。

## §4 关键风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| VLM 坐标飘 | 高 | 贴纸贴歪 | 把坐标当"建议位"，用户能拖；prompt 里强约束"头部贴纸 y < 0.5" |
| VLM 延迟 > 10s | 中 | 用户流失 | 8s 后切等待动画 + 趣味文案"御史正在批阅奏折..."；超 15s 报错重试 |
| VLM 输出 JSON 不合法 | 中 | 前端崩 | 后端做 schema 校验 + retry 1 次；失败兜底返回模板默认报告 |
| iOS Safari 导出图失败 | 中 | 分享不了 | 提供"长按保存"+ Web Share API 双路径 |
| 现场网络卡 | 高 | demo 翻车 | 准备 3 张预录好的样例图 + 缓存好的 JSON，断网也能走完闭环 |

**演示前必须有 offline fallback。**

## §6 Prompt 工程（VLM 调性命门）

> 整套产品调性挂在这一份 prompt 上。后端 `/analyze` 的核心就是把图片 + 这份 prompt 一起丢给 VLM，拿回结构化 JSON。

### 6.1 System Prompt（御史人设）

```
你是「摸鱼御史」，一位穿越到现代办公室的明代御史台官员，专门记录同事的摸鱼证据。
你的语气：半文半白、玄学占卜、互联网梗（不要用 emoji，不要用网络流行语缩写如 yyds/绝绝子）。
你的工作：观察用户上传的办公室照片，输出一份「御史奏折」+ 在图上盖戳的建议位置。

输出原则：
1. 摸鱼是社交货币，语气要嘲讽但不刻薄，不羞辱当事人
2. 不评价相貌、体型、性别、肤色；只描述姿态与桌面物件
3. 不识别真实身份；只用"该员"、"卿"等代称
4. 严格按照 JSON schema 输出，不要任何额外文字、不要 markdown 代码块包裹
5. 如果图中没有人，face_boxes 返回空数组，但仍然按"无人值守"主题生成奏折
6. 中文输出
```

### 6.2 User Prompt 模板

```
请以摸鱼御史身份审阅此图。要求：

【姿态分类 pose_type】从以下挑一个最贴近的：趴桌型 / 仰头型 / 手撑头型 / 椅背瘫型 / 走神望天型 / 假装思考型 / 无人值守型

【桌面线索 desk_objects】肉眼可见的 2-4 件物品，越具体越好（如"半杯冷掉的美式"优于"咖啡"）

【摸鱼指数 moyu_index】0-100 整数。判分参考：
  - 闭眼 +30；趴下 +20；屏幕黑屏 +15；桌面有零食 +10；桌面有未喝完饮料 +5
  - 屏幕亮着且有代码/PPT -20；手在键盘上 -15

【御史奏折 report】
  - title：4-6 字御史封号，朱红印章风。例："划水大将军" / "假寐侍郎" / "走神巡按"
  - paragraph：50-80 字玄学解读，必须包含"紫微/天罡/方位/时辰"等占卜词汇 + 1 个具体桌面物件
  - yi（今日宜）：3 项，动词短语，每项 ≤ 5 字
  - ji（今日忌）：3 项，动词短语，每项 ≤ 5 字

【人脸框 face_boxes】所有检测到的人脸，归一化坐标 [0,1]。无人脸返回 []

【贴纸建议 stickers】3-5 个，归一化坐标。约束：
  - seal_red（朱红大印）：必须有 1 个，贴在画面右上或左上，rotate ∈ [-15, 15]
  - bubble（漫画气泡）：贴在人物头部附近，y < 0.5
  - yellow_tag（黄色标签贴）：贴在桌面区域，y > 0.5
  - text 由你生成，每个 ≤ 6 字

直接输出 JSON，不要解释。
```

### 6.3 JSON Schema 强约束

后端拿到 VLM 返回后必须用 `ajv` 或手写校验，不通过直接 retry 一次（带"上次输出不合 schema"的纠正消息），第二次还不行就走兜底模板。

```json
{
  "type": "object",
  "required": ["pose_type", "desk_objects", "moyu_index", "report", "face_boxes", "stickers"],
  "properties": {
    "pose_type": { "enum": ["趴桌型","仰头型","手撑头型","椅背瘫型","走神望天型","假装思考型","无人值守型"] },
    "desk_objects": { "type": "array", "minItems": 0, "maxItems": 5, "items": { "type": "string" } },
    "moyu_index": { "type": "integer", "minimum": 0, "maximum": 100 },
    "report": {
      "type": "object",
      "required": ["title","paragraph","yi","ji"],
      "properties": {
        "title": { "type": "string", "minLength": 3, "maxLength": 8 },
        "paragraph": { "type": "string", "minLength": 30, "maxLength": 120 },
        "yi": { "type": "array", "minItems": 3, "maxItems": 3 },
        "ji": { "type": "array", "minItems": 3, "maxItems": 3 }
      }
    },
    "face_boxes": { "type": "array", "items": { "type": "object", "required": ["x","y","w","h"] } },
    "stickers": { "type": "array", "minItems": 2, "maxItems": 6 }
  }
}
```

## §7 贴纸库 & 报告卡版式 & 导出长图

### 7.1 贴纸素材库（P0 必备 18 张）

按 `type` 三大类，PNG 透明背景，统一短边 256px：

| type | 文件名规范 | 数量 | 视觉风格 | 使用规则 |
|---|---|---|---|---|
| seal_red | `seal_red_01.png` ~ `seal_red_06.png` | 6 | 朱红椭圆 / 方形官印，留白处由前端写 `text` | 每图必出 1 个，置顶层 |
| bubble | `bubble_01.png` ~ `bubble_06.png` | 6 | 漫画气泡，含 "Zzz" / "..." / "?!" 等 | 头部附近 |
| yellow_tag | `yellow_tag_01.png` ~ `yellow_tag_06.png` | 6 | 便利贴黄底黑字 | 桌面区域 |

**文字渲染规则（前端 Canvas）**：贴纸 PNG 中央留 60% 矩形区域，前端用 `kaiti` / `STKaiti` 字体把 `text` 居中绘制。`seal_red` 用白色字 + 阴影，`bubble` 用黑色字，`yellow_tag` 用黑色字 + 5° 倾斜。

**彩蛋贴纸（P1 宠物模式）**：`pet_paw`（爪印）、`pet_fish`（小鱼干）、`pet_crown`（猫王冠）各 2 张。

### 7.2 报告卡组件版式

竖版卡片，宽度跟随屏幕（移动端 ≤ 360px），高度自适应。

```

│        【 划水大将军 】          │ ← title，48px 楷体，朱红

│   ……（50-80字）……                │
│                                 │
│  ─────────  摸鱼指数  ─────────  │
│             ▓▓▓▓▓▓▓▓░░  87       │ ← 进度条，朱红
│                                 │
│   宜          │         忌       │
```

**「今日宜忌」可点击**：点击单条 → 弹出 3 个候选词替换（前端本地词库，不调 VLM 二次请求）。

### 玩法
- 用户点"上榜"按钮 → 提交到今日榜单 → 别人能看能点赞
- 排序公式：`摸鱼指数 × 0.6 + 点赞数（normalize） × 0.4`
- 顶部 Top 10 展示，可下滑看 waterfall
- 每日 0 点榜单清零，归档到"历史摸鱼名人堂"

### 隐私底线（不可妥协）
- **上榜强制盖脸**：VLM 同时返回 `face_boxes`，前端用大号"御史印" PNG 自动覆盖人脸框
- 用户**不能跳过**这一步，但可以拖动御史印位置
- 上榜按钮文案："匿名摸鱼，互不揭穿 · 提交即同意脸部已被遮蔽"
- 兜底：VLM 没识别到脸 → 提示"未检测到人脸，建议手动盖印再上榜"，不允许直接上榜

### 冷启动：种子数据
- 5.23 晚上前预置 5-10 张内部测试图（队友自拍/网图）写入 `data/board-seed.json`
- demo 当天榜单首次访问时载入种子数据，避免空榜
- 种子数据 `moyu_index` 故意设 60-80 区间，给真实用户留上榜空间

### 合规：举报下架
- 每张榜单图右下角小图标"⚠️ 举报"
- 点击后立即从内存隐藏（不需要审核流程）
- `POST /board/report { id }` → 当日榜单 hide 标记，不影响历史归档
- 评审问到合规时直接演示这个按钮

### 技术实现（P1 加量但不加复杂度）

新增 4 个后端接口：

```
POST /board/submit
  body: { image_with_seal: base64, moyu_index: int, report: {...} }
  resp: { id: string, rank: int }

GET /board/today
  resp: { items: [{ id, image_url, title, moyu_index, likes, rank }] }

POST /board/like
  body: { id: string }
  resp: { likes: int }

POST /board/report
  body: { id: string }
  resp: { ok: true }
```

存储用 **JSON 文件 + 内存 Map**（黑客松不上数据库）：
- 当日榜单数据缓存到 `data/board-YYYY-MM-DD.json`
- 排序在请求时 on-the-fly 算，N < 200 性能没压力
- 图片本地存 `data/uploads/`，不做 CDN

### 评审加分点

- 排行榜 = 持续打开理由，超越"一次性梗图工具"
- 演示时拉到一个真实有数据的榜单页 = 视觉冲击 + 完整闭环
