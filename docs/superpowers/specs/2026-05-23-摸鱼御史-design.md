## §1 产品定位与核心闭环

### 一句话定义
上传一张办公室日常照（摸鱼 / 出丑 / 沙雕瞬间皆可），AI 用搞怪御史调性给这张图打摸鱼分、起称号、写运势奏折；用户在自带贴纸库里拖拖拽拽做二创，导出一张带"段位徽章"的海报到朋友圈。

### 产品名
**摸鱼御史**（英文副标 MoYu Imperial）。

### 目标用户
互联网 / 办公室白领，20–35 岁，熟悉抖音梗文化。日常有"摸鱼时刻"想自我嘲讽 + 群里玩梗的需求。摸鱼是社交货币，不是负面词。

### 真实场景
下午 3 点，对面工位的同事头一歪睡着了；或自己摆拍一张装睡；或同事桌上一杯凉透的咖啡 + 黑屏电脑。你想发群里玩梗，但只发一张照片不够梗、配文又懒得想。打开摸鱼御史，3 秒拿到一张带"朱红印章 + 87 分摸鱼指数 + 划水大将军"段位徽章和一段中二解读的海报，然后你可以再亲手拖几张搞怪贴纸上去做二创。

### 核心闭环（5 步，全程 < 60s）

| # | 步骤 | 说明 |
|---|---|---|
| 1 | **触发** | H5 首页大按钮「开始审阅」→ 调摄像头 / 相册 |
| 2 | **AI 审阅** | 单次 VLM 调用 → 返回 `{ 评分, 等级, 称号候选, 运势奏折, 桌面线索, 人脸框 }`（**不返回贴纸坐标**，贴纸完全交给用户） |
| 3 | **出海报** | 前端按模板渲染：朱红印章 + 等级徽章 + 大字称号 + 原图（无贴纸）+ 奏折 + 宜忌 |
| 4 | **二创编辑** | 用户像修图 app 一样拖贴纸、加自定义文字气泡、一键换称号 |
| 5 | **分发** | 一键导出竖版 1080×1920 长图，保存 / 分享 |

### 评审锚点对应（赛道四）

| 维度 | 权重 | 我们怎么打 |
|---|---|---|
| 场景与问题洞察 | 15% | 办公室摸鱼是高频、真实、自然的视觉触发场景 |
| AI 能力与产品结合 | 30% | VLM 一次往返同时输出**评分 + 等级映射 + 多候选称号 + 玄学奏折**——AI 是创意编剧，不是识图器 |
| 体验完整性 | 20% | 触发 → 审阅 → 出海报 → 二创 → 分发，旅程闭合 |
| 用户价值感 | 20% | 从一张睡照变成可分享的梗素材 + 段位社交货币；同事之间比"谁段位高" |
| 创新性与延展 | 15% | 视觉理解 + LLM 玩梗 + 修图二创三件套，可扩展自拍 / 宠物 / 视频抽帧 |

### MVP 范围

**P0 必做**：核心闭环 5 步、6 档等级系统、18 张贴纸库、自定义文字气泡、海报导出。

**P1 升级**：今日摸鱼榜 + 强制脸部盖印（见 §15）。

**P2 不做**：跨次连载叙事（多图编织平行世界）、AI 重绘魔改、登录账号、人脸识别比对。

## §2 系统架构

```
┌─────────────────────┐         ┌──────────────────────┐         ┌─────────────────┐
│  H5 前端（移动端）   │  HTTPS  │   后端 BFF (Node)    │  HTTPS  │   VLM API       │
│  Vite + Vue/React   │ ──────▶ │   单一 /analyze 接口 │ ──────▶ │  (豆包/4o/...)  │
│  Canvas + 手势      │ ◀────── │   prompt + 校验      │ ◀────── │                 │
└─────────────────────┘  JSON   └──────────────────────┘  JSON   └─────────────────┘
        │
        │ 静态资源
        ▼
   贴纸 PNG 库 ×18
   等级印章 SVG ×6
   字体（楷/宋/汉仪滑稽）
```

### 切分理由

- **前端扛 80% 工作量**：Canvas 渲染、贴纸拖拽 / 缩放 / 旋转 / 删除、文字气泡编辑、海报合成
- **后端只做一件事**：包一层 prompt + 把 API key 藏起来 + JSON schema 校验。不做业务逻辑、不存图
- **VLM 单次往返**：不做多轮对话，token 可控、延迟可控（目标 P95 < 8s）
- **VLM 选型**：豆包 vision-pro（中文调性 + 字节生态 + JSON 稳定性）。备选 GPT-4o（豆包 JSON 飘了第 6h 切换）

## §3 模块拆分

### 前端 5 个模块

| 模块 | 职责 | 难点 |
|---|---|---|
| Capture | 调摄像头 / 相册、压缩到 1024px、上传 | 移动端兼容 |
| Analyzer Client | 调 `/analyze`、loading 动画、错误兜底 | 等 8s 不能让用户走 |
| Stage | Canvas 渲染原图 + 贴纸 / 文字图层 + 手势 | 多指缩放 / 旋转 |
| ToolBar | 底部工具栏：贴纸 / 文字 / 称号 三 tab | 状态管理、撤销 |
| Exporter | Canvas + 海报模板合成竖版长图，下载 / 分享 | iOS Safari 下载坑 |

### 后端接口契约

```
POST /analyze
  body: { image: base64 }
  resp: {
    pose_type: "趴桌型",
    desk_objects: ["半杯冷美式", "青轴键盘"],
    moyu_score: 87,                            // 0-100 整数
    level_tier: "摸鱼大将军",                  // 等级档（前端按此查配色 / 印章）
    title_candidates: [                        // AI 现抽的 3 个候选称号
      "划水大将军", "假寐侍郎", "摸鱼世家"
    ],
    report: {
      paragraph: "紫微星偏移3度，案上美式已凉...",  // 50-80 字
      yi: ["摸鱼", "划水", "假装思考"],
      ji: ["开会", "改PPT", "接电话"]
    },
    face_boxes: [                              // 人脸归一化框，仅做"封脸贴纸"建议位
      { x: 0.32, y: 0.18, w: 0.24, h: 0.28 }
    ]
  }
```

**注意**：相对 v1，移除 `stickers` 字段（贴纸完全由用户从工具栏拖入），新增 `moyu_score` / `level_tier` / `title_candidates`。

## §4 等级系统（MVP 主打玩法）

VLM 返回的 `moyu_score` 不再只是装饰数字，而是映射成"段位称号"，让用户有"我打到几段"的爽感。

### 6 档等级表

| 分数段 | level_tier | 主配色 | 印章风格 | 视觉特殊处理 |
|---|---|---|---|---|
| 0-20 | 打工新丁 | `#9aa1a8` 灰白 | 木质方印 | 朴素 |
| 21-40 | 划水学徒 | `#3b6fa0` 青蓝 | 铜质圆印 | 朴素 |
| 41-60 | 摸鱼修士 | `#3f8c5a` 翠绿 | 玉质椭印 | 印章自带细金边 |
| 61-80 | 划水侍郎 | `#7a3c8f` 紫绛 | 银质官印 | 印章自带粗银边 |
| 81-95 | 摸鱼大将军 | `#d4222b` 朱红 | 朱红大印 | 印章描金边 + 微抖动动画 |
| 96-100 | **假寐天尊** | `#d4222b` 朱红 + 金 | 朱红玺印 | 七彩光晕 + 持续呼吸动画（demo 主爆点） |

`title_candidates` 是 AI 在该等级内现抽的 3 个具体称号（不依赖前端预制词库），用户可在工具栏「称号」tab 一键切换。

### 等级映射规则
- 前端按 `level_tier` 直接查表渲染配色 / 印章
- AI 输出的 `moyu_score` 与 `level_tier` 必须一致；schema 校验：score 0-20 时 tier 必须是「打工新丁」，依此类推。不一致则后端 retry 一次，仍不一致走兜底模板。

### 评审 demo 抓手
准备 1 张极佳样图（趴桌 + 凉咖啡 + 黑屏 + 闭眼可见），AI 几乎稳定打到 95+，金边光晕 + 呼吸动画一出 → 评审现场视觉爆点。备 2 张兜底图覆盖 30 分、65 分两档作"等级谱"对比演示。

### 5.1 海报模板（先渲染、可编辑）

```
┌─────────────────────────────┐
│  ▌摸鱼御史奏折   甲辰年      │  顶部标题栏（朱红描边）
├─────────────────────────────┤
│       〖摸鱼大将军〗         │  等级档（小字 14px，等级配色）
│      【 划水大将军 】        │  大字称号（48px 楷体，等级配色）
│       摸鱼指数 ▓▓▓▓ 87        │  评分进度条
├─────────────────────────────┤
│                             │
│   [改造后的原图区]           │  主体 55%，用户在此拖贴纸
│                             │
├─────────────────────────────┤
│  紫微星偏移3度，案上美式      │
│  已凉……（50-80字）            │
│  ─────────────────────       │
│  宜  摸鱼 / 划水 / 假装思考   │
│  忌  开会 / 改PPT / 接电话    │
├─────────────────────────────┤

```

**配色**（沿用 v1）：底 `#f4f1ea` 米色 / 主朱红 `#d4222b` / 字深灰 `#2a2830` / 等级配色按 §4 表替换。

### 5.2 底部工具栏（弹出式，三个 tab）

| Tab | 内容 | 用户操作 |
|---|---|---|
| 🏷️ **贴纸** | 18 张预备（朱红印章 ×6 / 漫画气泡 ×6 / 便利贴 ×6）+ 1 张「御史封脸大印」置顶 | 点击 → 粘到画布中心 → 拖到位 |
| ✏️ **文字** | 输入文字 → 选字体（楷/宋/汉仪滑稽）→ 选配色（5 种预设） | 输入文字 → 粘到画布 |
| 👑 **称号** | 当前等级的 3 个 AI 候选称号（来自 `title_candidates`） | 一键替换海报上的称号 |

**画布交互**：长按元素 → 进入编辑态 → 八方向缩放控制点 + 旋转柄 + 删除按钮（×）。仿抖音通用编辑器，零学习成本。

**撤销**：右上角 ↶ 按钮，保留最近 10 步操作历史。

### 5.3 贴纸库清单（MVP 必备 18 张）

| type | 文件名 | 数量 | 视觉风格 | 文字渲染 |
|---|---|---|---|---|
| seal_red | `seal_red_01..06.png` | 6 | 朱红椭圆 / 方形官印，中心 60% 留白 | 白色楷体 + 阴影 |
| bubble | `bubble_01..06.png` | 6 | 漫画气泡（Zzz / … / ?! / 哼 / 啊 / 喵） | 黑色楷体 |
| yellow_tag | `yellow_tag_01..06.png` | 6 | 便利贴黄底黑字 | 黑色楷体 + 5° 倾斜 |

**额外 1 张**：`face_seal_big.png` 御史封脸大印，工具栏「贴纸」tab 第一张，前端默认在 `face_boxes` 上方做"建议位"高亮，引导用户主动盖脸再分享群里。

**前端文字渲染规则**：贴纸 PNG 中央留 60% 矩形透明区，前端用 Canvas 居中绘制用户输入的文字（≤ 6 字）。

### 5.4 隐私保护

MVP 不强制盖脸（强制是上榜场景，本 MVP 不做榜单）。但通过 UI 引导：
- 后端返回 `face_boxes` 后，前端在每张人脸上画一个虚线提示框
- 工具栏「贴纸」tab 第一张永远是封脸大印 + 高亮"建议"标签
- 文案提示："**想发群里？建议给同事盖个脸保平安 🙈**"

### 5.5 导出长图

跟 §5.1 海报模板布局一致，1080×1920 PNG，底部带二维码。

## §6 Prompt 工程（VLM 调性命门）

整套产品调性挂在这一份 prompt 上。

### 6.1 System Prompt（御史人设）

```
你是「摸鱼御史」，一位穿越到现代办公室的明代御史台官员，专门记录同事的摸鱼证据。
你的语气：半文半白、玄学占卜、互联网梗调（不要 emoji，不要用 yyds/绝绝子 等流行语缩写）。
你的工作：观察用户上传的办公室照片，给出摸鱼评分 + 段位称号 + 一份御史奏折。

输出原则：
1. 摸鱼是社交货币，语气嘲讽但不刻薄，不羞辱当事人
2. 不评价相貌、体型、性别、肤色；只描述姿态与桌面物件
3. 不识别真实身份；只用"该员"、"卿"等代称
4. 严格按照 JSON schema 输出，不要额外文字、不要 markdown 代码块包裹
5. 中文输出
```

### 6.2 User Prompt 模板

```
请以摸鱼御史身份审阅此图。要求：

【姿态分类 pose_type】从以下挑一个最贴近的：
  趴桌型 / 仰头型 / 手撑头型 / 椅背瘫型 / 走神望天型 / 假装思考型 / 无人值守型

【桌面线索 desk_objects】肉眼可见的 2-4 件物品，越具体越好（"半杯冷美式" 优于 "咖啡"）

【摸鱼评分 moyu_score】0-100 整数。判分参考：
  - 闭眼 +30；趴下 +20；屏幕黑屏 +15；桌面有零食 +10；桌面有未喝完饮料 +5
  - 屏幕亮着且有代码/PPT -20；手在键盘上 -15
  评分要稳健，能根据视觉信号合理推断。

【段位 level_tier】根据 moyu_score 严格映射，**不可错档**：
  - 0-20   → 打工新丁
  - 21-40  → 划水学徒
  - 41-60  → 摸鱼修士
  - 61-80  → 划水侍郎
  - 81-95  → 摸鱼大将军
  - 96-100 → 假寐天尊

【候选称号 title_candidates】3 个具体称号，必须与 level_tier 调性一致：
  - 4-6 字、朱红印章风
  - 第一个为推荐主称号（最贴该图调性），后两个为备选风味
  - 例（划水侍郎段位）：["假寐侍郎", "神隐巡按", "走神判官"]

【御史奏折 report】
  - paragraph：50-80 字玄学解读，必须包含 "紫微/天罡/方位/时辰" 等占卜词 + 1 个具体桌面物件
  - yi（今日宜）：3 项，动词短语，每项 ≤ 5 字
  - ji（今日忌）：3 项，动词短语，每项 ≤ 5 字

【人脸框 face_boxes】所有检测到的人脸，归一化坐标 [0,1]。无人脸返回 []

直接输出 JSON，不要解释。
```

### 6.3 JSON Schema 强约束

后端用 `ajv` 校验。不通过 retry 1 次（带"上次输出不合 schema"纠正消息），第二次还不行走 §6.5 兜底。

```json
{
  "type": "object",
  "required": ["pose_type", "desk_objects", "moyu_score", "level_tier", "title_candidates", "report", "face_boxes"],
  "properties": {
    "pose_type": { "enum": ["趴桌型","仰头型","手撑头型","椅背瘫型","走神望天型","假装思考型","无人值守型"] },
    "desk_objects": { "type": "array", "minItems": 0, "maxItems": 5, "items": { "type": "string" } },
    "moyu_score": { "type": "integer", "minimum": 0, "maximum": 100 },
    "level_tier": { "enum": ["打工新丁","划水学徒","摸鱼修士","划水侍郎","摸鱼大将军","假寐天尊"] },
    "title_candidates": { "type": "array", "minItems": 3, "maxItems": 3, "items": { "type": "string", "minLength": 3, "maxLength": 8 } },
    "report": {
      "type": "object",
      "required": ["paragraph","yi","ji"],
      "properties": {
        "paragraph": { "type": "string", "minLength": 30, "maxLength": 120 },
        "yi": { "type": "array", "minItems": 3, "maxItems": 3 },
        "ji": { "type": "array", "minItems": 3, "maxItems": 3 }
      }
    },
    "face_boxes": { "type": "array", "items": { "type": "object", "required": ["x","y","w","h"] } }
  }
}
```

**score / tier 一致性校验**：schema 通过后再跑一遍 `validateScoreTierConsistency(score, tier)`，不一致则按 score 强制覆盖 tier。

## §7 关键风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| VLM 评分飘 | 中 | 等级跟图调性不符 | Few-shot + 严格判分参考；用户可在「称号」tab 自换称号兜底 |
| VLM 延迟 > 10s | 中 | 用户流失 | 8s 后切等待动画 + 趣味文案"御史正在批阅奏折..."；超 15s 报错重试 |
| VLM JSON 不合法 | 中 | 前端崩 | schema 校验 + retry 1 次；失败走 §6.5 兜底 |
| score / tier 不一致 | 中 | 等级显示乱 | 后端按 score 强制覆盖 tier，前端不感知 |
| iOS Safari 导出失败 | 中 | 分享不了 | 提供"长按保存"+ Web Share API 双路径 |
| 现场网络卡 / VLM 抽风 | 高 | demo 翻车 | 3 张预录图 + 缓存 JSON（30 / 65 / 95+ 三档），`?offline=1` 走纯前端 |

**演示前必须有 offline fallback。**
