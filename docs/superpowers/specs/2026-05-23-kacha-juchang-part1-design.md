## §1 Part 1 产品定位与核心闭环

### 一句话定义（Part 1）
上传一张办公室日常照（摸鱼 / 出丑 / 沙雕瞬间皆可），AI 用古代批阅口吻给这张图打摸鱼分、起称号、写运势奏折，**并自动叠 1-2 个相关贴纸**作为初始构图；用户在自带贴纸库里继续拖拽 / 加文字 / 切称号做二创，导出一张带"段位徽章"的卡片到朋友圈，或直接进入 Part 2 互动剧情。

### Part 1 在产品中的位置
- **产品名**：咔嚓剧场（统一品牌，详见 ADR-005）。Part 1 是数据入口，Part 2 是数据出口
- **首期主题**：摸鱼（古代批阅氛围作为视觉语言）
- **Part 1 输出**：可分享的视觉运势卡片 + 驱动 Part 2 剧情生成的结构化 JSON（同一张照片在 Part 2 中复用）

### 目标用户
互联网 / 办公室白领，20–35 岁，熟悉抖音梗文化。日常有"摸鱼时刻"想自我嘲讽 + 群里玩梗的需求。摸鱼是社交货币，不是负面词。

### 真实场景
下午 3 点，对面工位的同事头一歪睡着了；或自己摆拍一张装睡；或同事桌上一杯凉透的咖啡 + 黑屏电脑。你想发群里玩梗，但只发一张照片不够梗、配文又懒得想。打开咔嚓剧场（Part 1），3 秒拿到一张带"朱红印章 + 87 分摸鱼指数 + 划水大将军段位 + 上签签型"的卡片和一段中二解读，AI 已经自动给你贴了 1-2 个相关贴纸，然后你再亲手拖几张做二创。

### Part 1 核心闭环（5 步，全程 < 60s）

| # | 步骤 | 说明 |
|---|---|---|
| 1 | **触发** | H5 首页大按钮「开始审阅」→ 调摄像头 / 相册 |
| 2 | **AI 审阅** | 单次 VLM 调用 → 返回 `{ 评分, 段位, 签型, 称号候选, 运势奏折, 桌面线索, 人脸框, 初始贴纸建议 }` |
| 3 | **出卡片** | 前端按模板渲染：朱红印章 + 段位徽章 + 大字称号 + 原图 + 奏折 + 宜忌 + **AI 自动叠 1-2 个推荐贴纸** |
| 4 | **二创编辑** | 用户从工具栏继续拖贴纸 / 加自定义文字气泡 / 一键换称号 / 删改 AI 默认贴纸 |
| 5 | **分发或续作** | 一键导出竖版 1080×1920 长图 **或** 点 CTA「召见御史·演今日剧」进入 Part 2 |

### 评审锚点对应（赛道四，Part 1 视角）

| 维度 | 权重 | Part 1 怎么打 |
|---|---|---|
| 场景与问题洞察 | 15% | 办公室摸鱼是高频、真实、自然的视觉触发场景 |
| AI 能力与产品结合 | 30% | VLM 一次往返同时输出**评分 + 段位 + 签型 + 多候选称号 + 玄学奏折 + 初始贴纸建议**——AI 是创意编剧 + 视觉构图师 |
| 体验完整性 | 20% | 触发 → 审阅 → 出卡片 → 二创 → 分发/续作，Part 1 旅程闭合并对接 Part 2 |
| 用户价值感 | 20% | 从一张睡照变成可分享的梗素材 + 段位社交货币；进 Part 2 还能演自己的今日剧 |
| 创新性与延展 | 15% | 视觉理解 + LLM 玩梗 + AI 主动构图 + 修图二创，主题可扩展（首期摸鱼，未来可换） |

### Part 1 MVP 范围

**P0 必做**：核心闭环 5 步、6 档段位 + 5 档签型双系统、25 张贴纸库、AI 自动叠 1-2 个初始贴纸、自定义文字气泡、卡片导出、Part 2 CTA 入口。

**P1 升级**：今日摸鱼榜 + 强制脸部盖印（见 §15）。

**P2 不做**：跨次连载叙事、AI 重绘魔改、登录账号、人脸识别比对。

## §2 系统架构

```
┌─────────────────────┐         ┌──────────────────────┐         ┌─────────────────┐
│  H5 前端（移动端）   │  HTTPS  │   后端 BFF (Node)    │  HTTPS  │   VLM API       │
│  Vite + Vue/React   │ ──────▶ │   单一 /analyze 接口 │ ──────▶ │  (豆包/4o/...)  │
│  Canvas + 手势      │ ◀────── │   prompt + 校验      │ ◀────── │                 │
└─────────────────────┘  JSON   └──────────────────────┘  JSON   └─────────────────┘
        │
        │ 静态资源
        ▼
   贴纸 PNG 库 ×18
   等级印章 SVG ×6
   字体（楷/宋/汉仪滑稽）
```

### 切分理由

- **前端扛 80% 工作量**：Canvas 渲染、贴纸拖拽 / 缩放 / 旋转 / 删除、文字气泡编辑、海报合成
- **后端只做一件事**：包一层 prompt + 把 API key 藏起来 + JSON schema 校验。不做业务逻辑、不存图
- **VLM 单次往返**：不做多轮对话，token 可控、延迟可控（目标 P95 < 8s）
- **VLM 选型**：豆包 vision-pro（中文调性 + 字节生态 + JSON 稳定性）。备选 GPT-4o（豆包 JSON 飘了第 6h 切换）

## §3 Part 1 模块拆分

### 前端 5 个模块（Part 1）

| 模块 | 职责 | 难点 |
|---|---|---|
| Capture | 调摄像头 / 相册、压缩到 1024px、上传 | 移动端兼容 |
| Analyzer Client | 调 `/analyze`、loading 动画、错误兜底 | 等 8s 不能让用户走 |
| Stage | Canvas 渲染原图 + AI 初始贴纸 + 用户后续图层 + 手势 | 多指缩放 / 旋转 |
| ToolBar | 底部工具栏：贴纸 / 文字 / 称号 三 tab | 状态管理、撤销 |
| Exporter | Canvas + 卡片模板合成竖版长图，下载 / 分享 / 跳 Part 2 | iOS Safari 下载坑 |

### Part 1 后端接口契约

```
POST /analyze   // Part 1 唯一后端接口
  body: { image: base64 }
  resp: {
    pose_type: "趴桌型",
    desk_objects: ["半杯冷美式", "青轴键盘"],
    moyu_score: 87,                            // 0-100 整数
    sign_type: "上签",                          // 5 档签型：下下签 / 下签 / 中签 / 上签 / 上上签
    level_tier: "摸鱼大将军",                  // 6 档段位
    title_candidates: [                        // AI 现抽的 3 个候选称号
      "划水大将军", "假寐侍郎", "摸鱼世家"
    ],
    report: {
      paragraph: "紫微星偏移3度，案上美式已凉...",  // 50-80 字 = 运势批文
      yi: ["摸鱼", "划水", "假装思考"],
      ji: ["开会", "改PPT", "接电话"]
    },
    face_boxes: [                              // 人脸归一化框
      { x: 0.32, y: 0.18, w: 0.24, h: 0.28 }
    ],
    initial_stickers: [                        // AI 推荐初始构图（1-2 个）
      { id: "yellow_tag_02", text: "凉透了", x: 0.10, y: 0.78, rot: -5 },
      { id: "bubble_zzz", x: 0.62, y: 0.12, rot: 8 }
    ]
  }
```

**注意（v2.1 相对 v2）**：
- 新增 `sign_type`（5 档签型，与 `level_tier` 6 档**并存**，从 `moyu_score` 段映射）
- 新增 `initial_stickers`（1-2 个 AI 推荐贴纸位置，落实 ADR-005 偏离 6）
- `report.paragraph` 即新需求文档所说的"运势批文"
- 字段命名保持代码兼容，不重命名 `report` 为 `批文`

## §4 Part 1 段位 + 签型双系统（MVP 主打玩法）

VLM 返回的 `moyu_score` 映射出两套并存的标签：

- **段位**（6 档 `level_tier`）：用于卡片配色 / 印章风格 / 视觉特殊效果，是 Part 1 视觉的主战场
- **签型**（5 档 `sign_type`）：用于卡片右上的"签型徽章"，并作为 Part 2 剧情基调的输入

### 6 档段位表（视觉主线）

| 分数段 | level_tier | 主配色 | 印章风格 | 视觉特殊处理 |
|---|---|---|---|---|
| 0-20 | 打工新丁 | `#9aa1a8` 灰白 | 木质方印 | 朴素 |
| 21-40 | 划水学徒 | `#3b6fa0` 青蓝 | 铜质圆印 | 朴素 |
| 41-60 | 摸鱼修士 | `#3f8c5a` 翠绿 | 玉质椭印 | 印章自带细金边 |
| 61-80 | 划水侍郎 | `#7a3c8f` 紫绛 | 银质官印 | 印章自带粗银边 |
| 81-95 | 摸鱼大将军 | `#d4222b` 朱红 | 朱红大印 | 印章描金边 + 微抖动动画 |
| 96-100 | **假寐天尊** | `#d4222b` 朱红 + 金 | 朱红玺印 | 七彩光晕 + 持续呼吸动画（demo 主爆点） |

### 5 档签型表（剧情基调 + 卡片徽章）

| 分数段 | sign_type | 卡片签型徽章主色 |
|---|---|---|
| 0-20 | 下下签 | 深灰 `#5b5b5b` |
| 21-40 | 下签 | 蓝灰 `#5d6f88` |
| 41-60 | 中签 | 琥珀 `#c08a3e` |
| 61-80 | 上签 | 翠绿 `#3f8c5a` |
| 81-100 | 上上签 | 朱红 `#d4222b` + 金边（81-95 用普通朱红，96-100 假寐天尊段额外叠七彩光晕） |

**双系统一致性**：分数段决定一切。schema 校验 `moyu_score` 必须同时与 `sign_type`、`level_tier` 一致，不一致后端按 `moyu_score` 强制覆盖两者。

`title_candidates` 是 AI 在该段位内现抽的 3 个具体称号（不依赖前端预制词库），用户可在工具栏「称号」tab 一键切换。

### 评审 demo 抓手
准备 1 张极佳样图（趴桌 + 凉咖啡 + 黑屏 + 闭眼可见），AI 几乎稳定打到 95+，金边光晕 + 呼吸动画一出 → 评审现场视觉爆点。备 2 张兜底图覆盖 30 分、65 分两档作"段位 + 签型谱"对比演示。

## §5 Part 1 修图式编辑层（MVP 第二个加厚点）

### 5.1 Part 1 卡片模板（先渲染、可编辑）

```
┌─────────────────────────────┐
│  ▌咔嚓剧场·御史房批复  甲辰 │  顶部标题栏（朱红描边）

│   〖摸鱼大将军 · 上上签〗    │  段位 + 签型（小字 14px，双标签）

│       摸鱼指数 ▓▓▓▓ 87        │  评分进度条
├─────────────────────────────┤

│   [改造后的原图区]           │  主体 55%

**配色**（沿用 v1）：底 `#f4f1ea` 米色 / 主朱红 `#d4222b` / 字深灰 `#2a2830` / 段位配色按 §4 表替换 / 签型徽章独立配色叠在右上角。

### 5.2 AI 自动初始贴纸（v2.1 新增，落实 ADR-005 偏离 6）

VLM 返回的 `initial_stickers` 数组（1-2 个元素）由前端直接渲染到卡片上，作为"AI 已经帮你构图好了"的初始状态：

**约束**：
- 数量：1-2 个，不能多。多了用户改起来烦
- 位置：归一化坐标 [0,1]，**禁止与 `face_boxes` 重叠**（VLM prompt 要求避让，前端做兜底碰撞检测，若 AI 给的位置盖脸则前端自动平移）
- 选材：必须与 `desk_objects` 或 `pose_type` 强相关。例如桌上有"凉透的美式"→ 推荐黄便利贴贴上"凉透了"3 字；趴桌型 → 推荐漫画气泡 "Zzz"
- 可编辑：用户可拖动、缩放、旋转、删除 AI 默认贴纸（与自己拖的没差别）

**实现路径**：VLM prompt 增加 `initial_stickers` 字段约束 → schema 校验 → 前端渲染层把 AI 给的贴纸塞进图层栈底部（用户后续操作叠在上面）

### 5.3 底部工具栏（弹出式，三个 tab）

| Tab | 内容 | 用户操作 |
|---|---|---|
| 🏷️ **贴纸** | 25 张预备（朱红印章 ×6 / 漫画气泡 ×6 / 便利贴 ×6 / 段位印章 ×6）+ 1 张「御史封脸大印」置顶 | 点击 → 粘到画布中心 → 拖到位 |
| ✏️ **文字** | 输入文字 → 选字体（楷/宋/汉仪滑稽）→ 选配色（5 种预设） | 输入文字 → 粘到画布 |
| 👑 **称号** | 当前段位的 3 个 AI 候选称号（来自 `title_candidates`） | 一键替换卡片上的称号 |

**画布交互**：长按元素 → 进入编辑态 → 八方向缩放控制点 + 旋转柄 + 删除按钮（×）。仿抖音通用编辑器，零学习成本。AI 默认贴纸的删除/编辑跟用户贴纸完全一致。

**撤销**：右上角 ↶ 按钮，保留最近 10 步操作历史。

### 5.4 贴纸库清单（Part 1 MVP 必备 25 张）

| type | 文件名 | 数量 | 视觉风格 | 文字渲染 |
|---|---|---|---|---|
| seal_red | `seal_red_01..06.png` | 6 | 朱红椭圆 / 方形官印，中心 60% 留白 | 白色楷体 + 阴影 |
| bubble | `bubble_01..06.png` | 6 | 漫画气泡（Zzz / … / ?! / 哼 / 啊 / 喵） | 黑色楷体 |
| yellow_tag | `yellow_tag_01..06.png` | 6 | 便利贴黄底黑字 | 黑色楷体 + 5° 倾斜 |
| tier_seal | `tier_seal_01..06.png` | 6 | 6 档段位印章（与 §4 配色一致） | 段位文字 |

**额外 1 张**：`face_seal_big.png` 御史封脸大印，工具栏「贴纸」tab 第一张，前端默认在 `face_boxes` 上方做"建议位"高亮，引导用户主动盖脸再分享群里。

**前端文字渲染规则**：贴纸 PNG 中央留 60% 矩形透明区，前端用 Canvas 居中绘制用户输入的文字（≤ 6 字）。

### 5.5 隐私保护

Part 1 MVP 不强制盖脸（强制是上榜场景，本 MVP 不做榜单）。但通过 UI 引导：
- 后端返回 `face_boxes` 后，前端在每张人脸上画一个虚线提示框
- AI 自动叠的贴纸在生成时已避开 `face_boxes`
- 工具栏「贴纸」tab 第一张永远是封脸大印 + 高亮"建议"标签
- 文案提示："**想发群里？建议给同事盖个脸保平安 🙈**"

### 5.6 导出 + Part 2 跳转

- **导出长图**：跟 §5.1 卡片模板布局一致，1080×1920 PNG，底部带二维码
- **跳 Part 2**：CTA「召见御史·演今日剧」点击 → 把 `/analyze` 完整 JSON 透传给 Part 2 路由（同一张照片作为 seed，不再二次上传）

## §6 Part 1 Prompt 工程（VLM 调性命门）

整套 Part 1 调性挂在这一份 prompt 上。

### 6.1 System Prompt（御史人设，保留古代批阅氛围）

```
你是御史房派驻现代办公室的明代御史台官员，专门记录同事的摸鱼证据。
你的语气：半文半白、玄学占卜、互联网梗调（不要 emoji，不要用 yyds/绝绝子 等流行语缩写）。
你的工作：观察用户上传的办公室照片，给出摸鱼评分 + 段位 + 签型 + 一份御史奏折 + 1-2 个推荐初始贴纸。

输出原则：
1. 摸鱼是社交货币，语气嘲讽但不刻薄，不羞辱当事人
2. 不评价相貌、体型、性别、肤色；只描述姿态与桌面物件
3. 不识别真实身份；只用"该员"、"卿"等代称
4. 严格按照 JSON schema 输出，不要额外文字、不要 markdown 代码块包裹
5. 中文输出
```

### 6.2 User Prompt 模板

```
请以御史身份审阅此图。要求：

【姿态分类 pose_type】从以下挑一个最贴近的：
  趴桌型 / 仰头型 / 手撑头型 / 椅背瘫型 / 走神望天型 / 假装思考型 / 无人值守型

【桌面线索 desk_objects】肉眼可见的 2-4 件物品，越具体越好（"半杯冷美式" 优于 "咖啡"）

【摸鱼评分 moyu_score】0-100 整数。判分参考：
  - 闭眼 +30；趴下 +20；屏幕黑屏 +15；桌面有零食 +10；桌面有未喝完饮料 +5
  - 屏幕亮着且有代码/PPT -20；手在键盘上 -15
  评分要稳健，能根据视觉信号合理推断。

【段位 level_tier】根据 moyu_score 严格映射，**不可错档**：
  - 0-20   → 打工新丁
  - 21-40  → 划水学徒
  - 41-60  → 摸鱼修士
  - 61-80  → 划水侍郎
  - 81-95  → 摸鱼大将军
  - 96-100 → 假寐天尊

【签型 sign_type】同样按 moyu_score 段映射：
  - 0-20    → 下下签
  - 21-40   → 下签
  - 41-60   → 中签
  - 61-80   → 上签
  - 81-100  → 上上签

【候选称号 title_candidates】3 个具体称号，必须与 level_tier 调性一致：
  - 4-6 字、朱红印章风
  - 第一个为推荐主称号（最贴该图调性），后两个为备选风味
  - 例（划水侍郎段位）：["假寐侍郎", "神隐巡按", "走神判官"]

【御史奏折 report】（即新需求文档所说的"运势批文"）
  - paragraph：50-80 字玄学解读，必须包含 "紫微/天罡/方位/时辰" 等占卜词 + 1 个具体桌面物件
  - yi（今日宜）：3 项，动词短语，每项 ≤ 5 字
  - ji（今日忌）：3 项，动词短语，每项 ≤ 5 字

【人脸框 face_boxes】所有检测到的人脸，归一化坐标 [0,1]。无人脸返回 []

【初始贴纸 initial_stickers】推荐 1-2 个贴纸作为卡片初始构图。规则：
  - 数量 1-2 个，宁少勿多
  - 每个对象格式 { "id": "贴纸ID", "text": "可选文字≤6字", "x": 0-1, "y": 0-1, "rot": -15~15 }
  - 贴纸 ID 取值：yellow_tag_01..06 / bubble_01..06 / seal_red_01..06 / tier_seal_01..06
  - 位置 (x,y) **绝对禁止**与任何 face_box 重叠（保留 0.05 安全边距）
  - 文字内容必须与 desk_objects 或 pose_type 强相关（如"凉透了"对应凉咖啡，"Zzz"对应趴桌型）

直接输出 JSON，不要解释。
```

### 6.3 JSON Schema 强约束

后端用 `ajv` 校验。不通过 retry 1 次（带"上次输出不合 schema"纠正消息），第二次还不行走 §6.5 兜底。

  "type": "object",
  "required": ["pose_type", "desk_objects", "moyu_score", "sign_type", "level_tier", "title_candidates", "report", "face_boxes", "initial_stickers"],

    "desk_objects": { "type": "array", "minItems": 0, "maxItems": 5, "items": { "type": "string" } },
    "moyu_score": { "type": "integer", "minimum": 0, "maximum": 100 },
    "sign_type": { "enum": ["下下签","下签","中签","上签","上上签"] },
    "level_tier": { "enum": ["打工新丁","划水学徒","摸鱼修士","划水侍郎","摸鱼大将军","假寐天尊"] },

## §7 关键风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| VLM 评分飘 | 中 | 等级跟图调性不符 | Few-shot + 严格判分参考；用户可在「称号」tab 自换称号兜底 |
| VLM 延迟 > 10s | 中 | 用户流失 | 8s 后切等待动画 + 趣味文案"御史正在批阅奏折..."；超 15s 报错重试 |
| VLM JSON 不合法 | 中 | 前端崩 | schema 校验 + retry 1 次；失败走 §6.5 兜底 |
| score / tier 不一致 | 中 | 等级显示乱 | 后端按 score 强制覆盖 tier，前端不感知 |
| iOS Safari 导出失败 | 中 | 分享不了 | 提供"长按保存"+ Web Share API 双路径 |
| 现场网络卡 / VLM 抽风 | 高 | demo 翻车 | 3 张预录图 + 缓存 JSON（30 / 65 / 95+ 三档），`?offline=1` 走纯前端 |

**演示前必须有 offline fallback。**

## §10 Part 1 90s Pitch 脚本

```
【0-10s · 钩子】
下午三点，对面工位的同事头一歪睡着了。
