# ADR-006: 古风原型转主线前端

> 日期：2026-05-24
> 状态：✅ 已决
> 决策者：波尔卡德（队长）
> 关联：[ADR-005 · 咔嚓剧场对标新需求文档](./005-咔嚓剧场对标新需求文档.md)

## 背景

仓库里同时存在两套 Part 1 前端：

- `src/frontend/`：React 19 + Vite + TS，由 Gemini 一键产出。曾是 ADR-002 中钦定的主线，已实现卡片 + 二创 + 长图导出 + Part 2 剧情。
- `design/style-mockups/apps/guofeng.html`：风格对比稿之一（另两套 claude / verge / bugatti），原生 HTML + JS + 小型 sticker-engine。视觉是真正"古代批阅"——御史房黄页底、朱红印章、紫禁城水印、卷轴上下拉杆。

5.23 试演时发现：

- React 版本的视觉是"现代 SaaS + 偶尔出现的红色印章贴纸"，演示气质不古，评委观感与"摸鱼御史 / 古代批阅"主题脱节。
- 古风原型 HTML 反而把朱红印章、卷轴杆、紫禁城水印、楷体批文都做实了，演示一打开"古代御史房"扑面而来。
- 两套并行维护成本高，黑客松剩余时间不够双线推进。

## 决策

**Part 1 演示主线切换到 `design/style-mockups/apps/guofeng.html`**，所有新功能（含 ADR-005 偏离 6 的"AI 自动垫贴纸"）在它之上迭代。

`src/frontend/` 处理：

- **保留**可跑状态，不删不重命名，作为代码兜底与 Part 2 剧情（`storyEngine.ts` / `ComicStripExport.tsx`）的载体——Part 2 仍跑在 React 版上，不在本 ADR 切换范围内。
- 演示稿、海报、对外文案以古风原型截图为准。
- 不再主动把 React 版的新需求往上叠，新 commit 默认改 `design/style-mockups/apps/guofeng.html` 及其 `_shared/`、`_assets/`。

## 为什么

| 维度 | guofeng.html | src/frontend (React) |
|---|---|---|
| 视觉气质 | ✅ 古代御史房（卷轴/朱红印/紫禁城水印/楷体） | ❌ 现代 SaaS 偶配红章 |
| 真实素材 | ✅ gemini-3 产出 PNG 印章（24 张） + chroma-key 现场扒底 | ❌ 内嵌 SVG 矢量，不够"印泥" |
| Part 1 闭环 | ✅ 上传 → 卡片 → 贴纸 → 长图导出全跑通 | ✅ 跑通但更工程化 |
| Part 2 剧情 | ❌ 未实现 | ✅ 5 节点 + 配图 + 长图已实现 |
| 演示加分项 | ✅ 加载页"展卷"动画 + 双拉杆 + 红印动态盖印 | ⚠️ 标准 spinner |
| 维护成本 | 低（单文件 HTML + 几个小 JS module） | 中（React 工程 + 多组件） |

**取舍**：Part 1 演示视觉效果 > 工程规范度。Part 2 因为已在 React 版做完且涉及多状态/路由，**不切**，演示时 Part 1（guofeng）→ Part 2（React）跨载体跳转可接受（也可以直接演示 Part 1 的古风稿 + Part 2 的连环画静态截图）。

## 对项目其它内容的影响

- **CLAUDE.md**：新增"主线前端"表述规范条目 + 路由表条目（已在本 ADR 同次更新中完成）
- **ADR-005 偏离 6**："AI 自动垫贴纸"实现目标改为 `guofeng.html` 的 `autoPickSeals()` 函数；React 侧的 `src/frontend/src/utils/autoPickStickers.ts` 视为先期探索保留

- **devlog**：在 2026-05-24 当日 devlog 记一笔切换原因与生效范围
