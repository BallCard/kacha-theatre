## 📋 使用建议

### 赛前（今晚）
1. 每位队员选择1-2篇最相关的文章深度阅读
2. 填充对应的速查表内容
3. 团队讨论，提炼出3-5条最重要的经验

### 比赛中
1. 遇到问题时快速查表，看是否有类似经验
2. 记录新的问题和解决方案，赛后补充

### 赛后
1. 完整填充速查表
2. 写一篇自己的复盘文章
3. 沉淀为可复用的知识库

## 🎯 快速决策参考

### 技术选型
- [ ] 优先选择团队熟悉的技术栈
- [ ] API 要提前测试可用性和速度
- [ ] 准备备用方案（Plan B）

### 功能取舍
- [ ] 设计阶段砍掉 70% 功能
- [ ] 开发中期再砍 50%
- [ ] 演示时只展示核心功能

### 时间分配
- [ ] 前3小时：需求与设计（含砍功能）
- [ ] 中间12小时：核心功能开发
- [ ] 后5小时：体验优化
- [ ] 最后3小时：演示准备
- [ ] 预留2小时缓冲

### 团队协作
- [ ] 明确决策机制（谁拍板）
- [ ] 快速达成共识，先做再说
- [ ] 遇到问题及时沟通，不要闷头做
- [ ] 非技术成员负责砍功能和演示准备
