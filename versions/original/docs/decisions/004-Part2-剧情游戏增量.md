# ADR-004: Part 2 增量 — 在摸鱼御史之上加 5 节点互动剧情

**日期**：2026-05-23
**状态**：✅ 已决（待 5.23 晨会全员对齐）
**决策者**：队长 + 队友需求迭代

## 背景

5.23 凌晨，队友提交《咔嚓剧场需求文档》（见 [docs/requirements/](../requirements/咔嚓剧场需求文档-队友版-2026-05-23.docx)），提出一个新方向：

- **部分 1**：上传照片 → AI 生成今日运势卡
- **部分 2**：基于运势卡展开 5 节点互动剧情游戏，每节点 3 个 AI 动态生成的选项，最终导向 6 种差异化结局

该方向与当前 MVP v2（[Part 1 设计](../superpowers/specs/2026-05-23-kacha-juchang-part1-design.md)）存在两条路径冲突：

1. **是否保留"摸鱼"主题**：摸鱼版题材聚焦但题材较窄；通用运势版题材丰富但失去视觉触发锚点。
2. **是否推翻已有 MVP**：已完成的后端 T1-T13（VLM 单往返、6 档段位映射、demo 兜底）+ 前端已接入的编辑层在"纯换通用版"路径下基本作废。

## 决策

**选择折衷方案：保留摸鱼主题，把剧情游戏作为 Part 1 之后的纯增量。**

| 部分 | 内容 | 改动量 |
|---|---|---|
| **Part 1** | 现摸鱼御史 MVP v2（不动）：单图 → 摸鱼分 + 段位 + 御史奏折 + 海报 + 二创编辑 | ✅ 零改动 |
| **Part 2** | 奏折页新增「今日摸鱼实录·5 幕剧」入口 → 5 节点 LLM 剧情游戏 → 6 结局 → 连环画长图 | 🆕 纯增量 |

### Part 2 关键设计要点

- **5 节点 = 打工人的一天**：早晨 / 上午 / 午后 / 下午 / 临下班，每节点 3 选项
- **3 选项策略**：顺应天命（摸鱼）/ 逆天而行（认真干）/ 中立观望
- **宜忌生效**：Part 1 奏折里"今日宜假寐"→ 节点中选"假装思考"成功率 +80%；"今日忌开会"→ 选发言必翻车
- **6 结局**：天命应验 / 御史降罚 / 贵人相助 / 天降祥瑞 / 逆天改命 / 哭笑不得
- **AI 调用**：每节点调一次纯文本 LLM（不用 VLM，token 便宜延迟低），上下文 = Part 1 奏折 JSON + 历史选择
- **预生成策略**：节点 N+1 在用户读节点 N 时后台预出 3 个分支，体感等待 ≈ 0
- **调性统一**：御史腔半文半白贯穿，剧情对白允许"周报 / KPI / 开会 / 划水"现代办公词增强代入感

详见 [Part 2 设计文档](../superpowers/specs/2026-05-23-kacha-juchang-part2-design.md)。

## 理由

### 为什么保留摸鱼（不走纯通用版）

1. **保住赛道四视觉锚点**：摸鱼版"VLM 从办公室照片真实视觉信号判摸鱼证据"对应赛道四"真实自然的视觉触发场景 + 技术如何支撑体验展开"两大评审锚点；通用版变成"看张脸→随机抽签→编剧情"，视觉理解退化成贴图工具，赛道四 30% 的 AI 能力分会被稀释。
2. **避免推翻已有 12+ 提交工程**：后端 T1-T13 + 前端 MVP 接入按"摸鱼+单往返"设计，全部直接复用。
3. **调性稳定**：御史腔已写死在 prompt，保留摸鱼语境就保留了 system prompt，不会出现"御史奏折 + 网络热梗口语化"的语调割裂。

### 为什么补 Part 2（不维持原 v2 静态海报版）

1. **剧情游戏 = 强重玩 + 强分享**：同一张照片，不同选择 = 完全不同的连环画，重玩驱动远超静态海报。
2. **赛道四"体验完整性 + 用户价值感"加分**：从"看图打分"扩展到"看图玩剧情"，用户旅程更完整。
3. **办公室摸鱼短剧本身是抖音内容富矿**：被领导走过、群里被 @、装睡被抓、误打误撞升职……题材天然存在，5 节点足以撑出反转。

### 为什么不是纯通用版

| 维度 | 摸鱼版 + Part 2 | 纯通用运势版 |
|---|---|---|
| 视觉锚点 | ✅ 办公室真实场景 | ❌ 照片只是触发器 |
| AI 能力差异化 | ✅ VLM 真在判证据 | ❌ VLM 退化为贴图 |
| 题材丰富度 | ⚠️ 限办公室 | ✅ 任意生活场景 |
| 已有工程复用 | ✅ Part 1 零改动 | ❌ 后端前端大改 |
| 调性一致性 | ✅ 御史腔贯穿 | ❌ 御史皮 + 口语腔割裂 |
| 25h 工程可行性 | ✅ Part 2 纯增量 | ⚠️ 拆掉重做 |

**评分 5:1，选折衷方案。**

## 范围变更

### MVP v2 → MVP v2.1 范围调整

**新增 P0**：
- Part 2 剧情游戏入口（奏折页底部新按钮）
- `/plot/next` LLM 节点生成接口
- 5 节点剧情状态机（前端）+ 节点 N+1 预生成
- 6 结局映射规则 + 终章连环画长图导出

**保留 P0**（来自 v2）：
- Part 1 全部内容（单图打分 / 6 档段位 / 奏折 / 海报 / 18 张贴纸 / 文字气泡 / 称号切换 / 海报导出）

**降级到 P1**（如时间紧立刻砍）：
- Part 2 终章连环画长图（可降级为纯文本结局页 + 截图分享）
- 节点 N+1 预生成优化（可降级为串行调用 + loading 文案）
- "天命 PK" / "每日御批提醒"（队友文档里有，但本 MVP 不做）

**仍然不做**（继承 v2）：
- 跨次连载叙事（5-6 张照片编织平行世界）
- 摸鱼榜
- 人脸识别比对 / 登录 / 数据库

## 风险

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 5 节点 LLM 串行延迟 ≈ 15-20s | 高 | 用户中途流失 | 预生成 + 流式输出双路径；预生成在前 |
| LLM 剧情上下文飘 / 不一致 | 中 | 后续节点跟前面对不上 | 每次调用都传完整奏折 + 历史选择 JSON（< 1k tokens） |
| 6 结局判定逻辑复杂 | 中 | 出错把"天降祥瑞"显示成"御史降罚" | 结局判定纯前端规则（基于宜忌命中次数 + 段位），不依赖 LLM 决策 |
| Part 2 工程量超预算 | 中 | 联调时 Part 2 半成品 | 5.24 01:00 死线 Part 1 主闭环必须跑通；Part 2 跑不通可砍至纯文本结局 |
| 队友需求文档其他需求被默认丢弃 | 低 | 后续返工 | 本 ADR 已明确列出"采纳/不采纳"清单（见上方范围变更） |
